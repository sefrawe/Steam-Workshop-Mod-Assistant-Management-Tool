## 1. 目标与工作流

- **目标**：Mod 管理工具 V2 跑在 Linux（Mint）上——先源码版跑通主链路（下载→判决→确认），再出安装包（AppImage，唯一维护格式）。
- **三环工作流**：agent 在仓库本体改码（linux-port 分支）→ GitHub Actions 双平台跑 201 个测试 → 人眼（Surface Go 2 + U盘 Mint）实测 PTY/字体/下载/防复活。
- **铁律**：改动只在 `linux-port` 分支（基于 V2）；动完看 diff 再合；先源码后打包；Linux 包由 Actions ubuntu runner 构建，Mint 只下载实测。
- **仓库**：origin https://github.com/sefrawe/Steam-Workshop-Mod-Assistant-Management-Tool.git
  默认分支 V2；本地分支 V2 + linux-port。MIT。

### 10.1 启动链路三轮修整（main.py v8 → v10.2 全落地）

- **时间线实证收口（v8 引入）**：同一天、同文件夹、同用户，旧打包 exe 正常、新打包 exe 写 data/ 被拦——「长期不用信誉衰减」假说出局，「**信任按文件指纹（哈希）记录**」成为唯一自洽解释；重打包即清零；回退旧版重打包同样被拦（任何重打包 = 新哈希）；Windows 更新 / 卸载 VS2022 均排除（VS2022 不进打包产物，开发机环境改变不了 exe 指纹）。结论：**无签名发布线的观察期拦截是常态，代码层只能把最短出路直接递给用户**。

### 10.2 实测记录（启动期诊断）

- **探针三件套**（互斥体 + 文件锁全失败路径）：软件根建文件 OK / Temp errno 13 / data errno 13——观察期拦的是「新建数据文件」这个动作，不是整个目录；软件根能写不等于 data/ 能写，三个探针位缺一不可。

### 10.4 i18n 键漂移教训

- 本轮实测：代码侧长键加了「；或点下方按钮。」六个字，词表还是旧键——`t()` 整键精确匹配失败回退中文原文，后续短键命中英文 → **弹窗前半段中文后半段英文**的混合现场。修法：词表键与代码键逐字对齐。
- **流程强化**：改任何 `t()` 包裹的文案（哪怕一个标点）必须同步 `gui/i18n_en.json` + 跑 `tools/check_i18n_keys.py`——门禁本来就该抓这类漂移，本轮是漏跑才漏过去。本轮新增/修改键全部入表（守卫四键、单实例长键、探针三行、按钮"退出"/"以管理员身份重启"、守卫标题键等）。
